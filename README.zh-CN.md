# 稿伴 Draft Companion 中文文档

**[English README](README.md)**

围绕当前 Markdown 文稿讨论、审稿和改稿的 Obsidian 桌面插件。讨论留在侧栏，审阅和改稿建议先形成候选；0.3.0 也支持用户明确授权的局部执行，写入后有真实核验、操作记录和安全撤回。主要用于公众号文章创作，也可编辑伙伴规则用于其他题材。

**当前本地版本：0.4.0，本次没有公开或社区发布。请使用本项目 `dist/draft-companion/` 或 `dist/draft-companion-0.4.0.zip` 安装。** 更新及回退见 [0.4.0 更新说明](docs/UPDATE_0.4.0.md)，实现见 [技术说明](docs/IMPLEMENTATION_0.4.0.md)，已完成与待验证项目见 [验证记录](docs/VERIFICATION_0.4.0.md)。

侧栏顶部新增 **清空对话**：清除当前文稿的全部聊天记录、未发送输入和任务状态，保留正文、本文要求、批注及撤回能力。见 [0.3.1 更新说明](docs/UPDATE_0.3.1.md)。

## 0.4.0 每日选题

文稿信息行右侧的 **立即选题** 会独立运行完整流程，不需要在输入框里下指令，也不需要打开每日开关。目标固定为设置中绑定的选题库；切到其他笔记不会改变写入目标。聊天忙时任务排队，按钮可取消排队；运行时点击“停止”作废未提交内容。

在 **稿伴设置 → 每日选题** 编辑作者背景、读者、兴趣、排除项，以及服务和伙伴。默认北京时间 **09:00**；本机开关保存在 Obsidian 本地存储，其他同步设备不会因此自行启动。需要 Obsidian 打开，错过后只补最近一个到期日；失败不自动重试，可点击“立即选题”检查后重跑。

设置了时刻并不代表已经激活定时；需要单独打开本机开关。“立即选题”随时可以独立运行。本机 `personal_database` 已安装并启用 0.4.0，北京时间 09:00 开关已打开；首轮定时任务写入十个候选，其中五个优选已勾选，原有文稿内容保留。

公开来源为 AIHOT 的近期精选和热点，以及 Git Stars 的 AI 项目页。Git Stars 受阻时可使用已开启的 GitHub 官方接口补充，条目会标出实际来源。最多保留十个相关候选、其中零至五个优选；只有符合读者、问题、价值和公开材料依据的条目才会勾选。每轮最多两次模型请求；相同事实不会重复生成，单纯 star 或抓取时间变化不算进展。

采集使用 AIHOT `/api/v1/items`（最近 24 小时精选）和 `/api/v1/hot-topics`，GitHub 补充使用 `/search/repositories`，仓库原始材料使用 `/repos/{owner}/{repo}/readme`。来源请求不会携带模型服务密钥，整个选题库不会发送给模型。来源响应默认在内存中缓存 **128 条／16 MiB**，通过 ETag 条件请求复用未变正文；内容变化时更新，重启后清除，不写入知识库或同步。模型密钥、认证头和服务配置都不进入缓存。具体路径、读取限制和代理边界见 [实现说明](docs/IMPLEMENTATION_0.4.0.md)。

选题库的新日期置顶，原有内容完整保留。同日只补充新增条目与管理状态行，既有卡片、标题和勾选不覆盖。每个日期只显示一行推荐与备选数量；采集失败、接口详情和完整时间保存在插件运行记录，不占正文。

优选先显示独立大标题，再显示仅包含项目或事件名与短来源链接的 checkbox，避免文章标题跟着勾选变成删除线。正文保留一句中文简介、简短推荐理由和切入角度；开头、提纲和四个备选标题收进“写作预设”折叠块，提纲和备选使用无序条目，避免宿主自动续编号。“动笔前补充”也折叠，无缺口时不添加套话。`[x]` 表示稿伴选中，值得创作；不是文章已完成。“创作潜质”是编辑判断，不是流量概率，也不代表已经亲测或联网核验全部事实。

管理标记仍保存在原始 Markdown 中，用于去重和安全撤回；阅读与编辑界面会隐藏标记，直接选择标记所在行时显示原文。新卡片的中文简介在原有第二次模型请求中生成；旧 schema 4 记录无此字段也能读取，来源原文与事实指纹保持不变。整理已有自动内容必须先验证备份，只处理未经用户修改的批次，并同步更新撤回回执。

**查看** 打开来源、结果及本次新增的撤回入口；内容被重叠修改或版本不明时会阻止撤回。清空对话保留每日设置、运行记录和批次回执。普通聊天选题仍只修改 checkbox，完整卡片写入只属于此采集流程。

迁移和回退见 [0.4.0 更新说明](docs/UPDATE_0.4.0.md)，实际验收见 [0.4.0 验证记录](docs/VERIFICATION_0.4.0.md)。

真实来源和模型验证使用原配置的 `deepseek-v4.1-flash` 并保留流式设置。60 秒请求超时、显式调整为 180 秒后第二阶段仍超时，再显式调整为 300 秒后约 281 秒完成；这些是分开的人工验证，没有自动重试或切换模型。自动化、模拟服务、真实模型与实际安装结果分别记录，不能互相替代。

## 0.3.0 使用流程

打开文稿并检查侧栏显示的目标路径。“更多操作”提供讨论、审阅、改稿建议、选题、标题和大纲任务；角色规则仍可编辑，角色名称或规则不会授予写入权限。

- **只讨论、拟标题或列大纲**：选择对应任务，或明确说“只讨论，不要修改”。结果只留在侧栏，零写入。
- **审阅或预览改法**：生成批注或改稿候选，检查预览后采纳、忽略或放弃。此时不会直接修改正文。
- **直接修改一处**：在编辑器选中一个段落，明确要求如何修改；也可在本轮逐字引用唯一原句。插入时先在正文放置光标，再明确说“在当前光标插入……”。位置在发送时冻结，不随后续光标或文稿切换移动。
- **选一个题并打勾**：打开任务式选题库，或在“更多操作 → 绑定选题库”中选择文件，再说“选一个值得写的项目并打勾”。默认只改该条 checkbox，不写入理由或标题；首推和备选标题留在侧栏。只要建议时说“只推荐，不要勾选”。链接不会自动抓取。
- **检查与撤回**：实际操作卡片显示已写入、定位与撤回。局部撤回可以保留后续无关修改；原句、上下文改变或版本不明时要求重新检查。写入和定位分别反馈，定位失败不会掩盖已完成写入。

明确的“帮我选择一些适合的选题”会直接进入选题流程，无需另一次模型分类；没指定数量时按读者价值和材料质量选择 0–5 条，不凑数；明确数量时尊重要求，材料不足先说明。理由和五个标题只放侧栏。“只推荐，不要勾选”保持零写入。

工具循环最多六轮，每轮最多八个调用；不明确的意图判断和首次自动协议探测可能另有请求。停止只作废尚未提交的调用，已经完成的修改保留回执；后续回复失败也不会把已写入误报为零修改。历史 `summary/edits` 或改稿 JSON 只读展示，不能从旧消息自动执行。

有效 schema 1/2 数据会先逐字节备份并校验，再升级 schema 3，保留服务、密钥引用、编辑过的角色、偏好、历史和旧修改资料。桌面恢复在可用时核对原生文件身份；旧记录没有强身份且没有同一现场 `TFile` 移交时，旧候选和撤回待重检，历史继续保留。回退应同时恢复对应旧版数据，不能只换运行文件。详见 [0.3.0 更新与回退](docs/UPDATE_0.3.0.md)。

“选题编辑”新增参考 [bigpeng-hot-gzh](https://github.com/BigPengSays/bigpeng-hot-gzh) 改编的八类选题方法和七类标题角度。关键词或素材先生成最多三个方向；明确主题或草稿可直接生成不同角度的标题。每条都说明材料依据与正文承诺，缺少事实时指出缺口，不编造数字或亲测经历。规则仍可编辑，没有新增联网搜索，也不预测爆款。更新、配置保留和验证见 [0.2.1 说明](docs/UPDATE_0.2.1.md)。

此前 0.2.2 优化侧栏空间：长文本粘贴后输入框只在约五行内增长，并在框内滚动，发送和停止按钮保持可见；“更多操作”改为可滚动的浮层菜单，不再撑开侧栏。空对话会紧凑显示，长历史继续在独立阅读区滚动；很矮的侧栏可整体滚动以保留操作入口。详见 [布局更新说明](docs/UPDATE_0.2.2_LAYOUT.md)。

## 0.2.0 公众号批注流程

打开文稿，在稿伴切换到“批注”，留空点击“审阅”即可生成重点句级意见；也可输入本轮审阅要求。默认审阅真实单选区或全文，顶部显示当前范围。角色仍使用你编辑过的规则。

1. 原文的有效意见会高亮并显示编号。点击批注或高亮查看；重复原句需要上下文唯一定位，否则只能查看旧引用。
2. 点击“预览”打开独立的稿伴审阅标签，不替换原编辑器。默认“修订”，可切换“原文 / 修订 / 改后”和附近段落 / 全文。只有当前意见进入内存预览，其他未采纳意见仍保留原文。
3. 点击“采纳”只写入这一条新句；“忽略”记录你的拒绝，不改正文。成功后自动选中下一条有效待处理意见，失败时停留当前条目。
4. 在“已处理”中选择已采纳意见，可安全验证时点击“撤回”，只恢复对应原句，保留后续无关改动。原句、关键依据或逆向锚点被修改后会要求重新检查。
5. “追问”只讨论当前意见；“再改一版”生成新的候选版本，旧版本保留并标为被替代。原始作者不会随角色切换或改名改变。

源文和 Live Preview 支持高亮；阅读模式可使用“切换到编辑模式并定位”。所有模型结果需要完整结束并通过结构校验，取消、截断和无效 JSON 不会产生执行按钮。再次审阅会统计新增与完全重复的意见，已忽略意见不会自动恢复。

聊天和整篇改稿继续保留；快捷任务、整篇改稿、选区改稿与删除入口在“更多操作”中。Enter 换行，⌘ / Ctrl + Enter 发送；中文组词时不会发送。本文要求默认折叠。侧栏草稿与滚动位置按文稿及对话/批注分别保存。

数据首次从 schema 1 升级时，插件先在安装目录保存 `data-schema1-时间戳.backup.json`，备份校验成功才写入 schema 2。服务、密钥引用、角色、偏好、历史、旧整篇候选与撤回记录均保留。迁移和回退见 [0.2.0 更新说明](docs/UPDATE_0.2.0.md)，验证记录见 [0.2.0 验证](docs/VERIFICATION_0.2.0.md)。

## 安装

需要 **Obsidian 桌面版 1.11.4 或以上**。最低版本依据所用官方密钥 API 确定；实际测试的应用版本、已完成与待完成验证见 [0.4.0 验证记录](docs/VERIFICATION_0.4.0.md)。目前仅支持桌面端。

1. 先在独立测试 Vault 中安装并试用，使用 [0.3.0 合成选题与改稿文稿](fixtures/稿伴0.3.0合成选题与改稿.md)；此前的 [合成测试文稿](fixtures/测试文稿.md) 继续保留。
2. 使用本地生成的 `dist/draft-companion-0.4.0.zip` 并解压，或直接使用 `dist/draft-companion/`。文件夹中应只有 `main.js`、`manifest.json`、`styles.css` 三个运行文件。GitHub Release 提供的是先前公开版本。
3. 手动将该文件夹放入所选 Vault 的插件目录：`<Vault>/.obsidian/plugins/draft-companion/`。
4. 在 Obsidian 的社区插件设置中允许社区插件、刷新列表并启用 **Draft Companion**。
5. 点击左侧铅笔按钮，或在命令面板运行 **Draft Companion: 打开创作侧栏**。

更新时只替换上述三个运行文件，然后重载插件。保留既有插件数据即可保留配置、编辑过的伙伴与本文会话。分发包不含用户数据或密钥。

社区目录已发布。客户端列表同步后，可在 Obsidian 设置 → 社区插件 → 浏览中搜索 `Draft Companion` 并安装。目录当前要求英文介绍，中文名称“稿伴”作为插件界面名称，不保证可用于市场搜索。此后在“检查更新”中获取新版；官方社区插件不会静默自动更新。推送源码不会让已安装插件立即更新，维护者需要发布新的版本。发布维护步骤见 [发布说明](docs/RELEASING.md)。

## 配置服务和模型

在侧栏点击“设置”，添加兼容 OpenAI 聊天接口的服务。填写名称和 API 根地址，例如 `https://api.openai.com/v1` 或你服务商提供的自定义路径。插件只追加 `/models` 与 `/chat/completions`，不会猜测或补上 `/v1`，不支持其他服务商的全部原生协议。

通过 **Obsidian 密钥管理器**选择或新建 API 密钥。插件普通配置保存密钥名称引用，运行时用官方 `SecretStorage` 取用；本项目不自行实现加密，也不对底层存储方式作额外承诺。无需认证的本地服务可留空。删除服务只删除其配置，保留 Obsidian 中可供其他插件共享的密钥。

填写地址并选择密钥后，服务配置窗口会自动获取模型列表；无需密钥的服务可点击“获取模型”。直接在同一个窗口搜索、点击模型并“保存配置”，无需去服务商后台查询。已有服务可点“更换模型”重新获取；“刷新模型”可更新列表。更换地址或密钥会取消旧请求并重新获取，关闭窗口也会取消请求。模型获取不发送文稿，也不会自动选择第一个模型。

保存后可执行“独立聊天测试”。列表成功表示服务返回了这些模型，不保证每个模型都有聊天权限；模型列表和聊天测试分别显示结果。认证、网络、接口不支持、格式不兼容、服务错误会给出不同提示。列表接口不可用时，可重试，或在高级选项中手动填写模型 ID；也可“暂不选模型，保存服务”，以后再配置。

高级选项新增“工具协议”：自动检测、原生工具和结构化兼容。自动检测只发送合成协议探测，不含文稿；认证、网络或超时失败不会暗中换协议。两条执行路径使用相同本地权限和受限工具校验，结构化兼容不会把普通聊天或历史 JSON 当成命令。

可添加、编辑和删除多个服务，首版所有伙伴使用侧栏当前选定的服务与模型。请求开始后固定这一次的连接、模型和规则；生成途中调整配置只影响下一轮。

默认流式输出；不支持流式的服务可以在配置中关闭。可设置 1–600 秒超时和服务已确认的上下文容量。容量校验使用粗略估算并预留输出余量，只有配置容量上限后才进行本地预检；没有模型容量元数据时不猜上限。超限会提示，不会偷偷截断全文、改成摘要或删除历史。

## 写作流程

打开并聚焦一篇 Markdown 文稿后，稿伴会绑定最近聚焦的文稿。点击侧栏输入框不会解除绑定；始终检查侧栏显示的文稿路径。可以从任意阶段开始，不必填完表单或先经过选题、大纲。

预设包含 **选题编辑、大纲编辑、初稿作者、责任编辑、改稿编辑、标题与发布检查**。每个伙伴有独立规则、默认讨论或改稿方式及快捷任务。快捷任务只填入输入框，确认后才发送。设置中可新增、复制、编辑和删除伙伴；预设只在首次初始化时创建，重启不会覆盖已编辑的规则。

“全局创作偏好”用于保存读者、语气和常写题材；侧栏的“本文要求”按文稿保存。两者均可留空，不会推断公众号名称或作者署名。

- **讨论、标题、大纲**：结果留在侧栏，不会写入文稿。
- **改稿建议 + 正文**：理解最新全文，生成待确认的正文候选，保护开头 YAML frontmatter 的原始字符。
- **改稿建议 + 选区**：理解全文，候选仅针对发送时选择的那一个连续范围。需要编辑模式且选区不为空；选区进入 frontmatter 时会阻止修改。
- **自动范围**：发送时有单个非空选区就使用选区，否则使用正文。
- **明确局部执行**：按上方 0.3.0 流程使用冻结授权范围或光标，成功结果以本地操作记录为准。

每次发送都重新取得文稿最新全文，并加入本文要求、全局偏好、当前伙伴规则和本文历史。选区在发送时固定；生成后挪动光标或选择其他文字不会改变旧候选的写入位置。

## 预览、应用和撤回

整篇改稿成功后点击“预览差异”，检查增加与删除的内容，再“应用整批修改”或“放弃候选”。整篇候选仍采用严格全文校验；0.2.0 句级批注使用上方逐条流程。候选说明与待核实事项不写入正文；空回答、无效 JSON、截断响应不会成为可应用改稿。需要删除文字时使用“删除当前范围”，同样先生成删除候选并预览确认。

从发送到应用期间，只要正文发生任何变化，旧候选就会失效，避免覆盖新内容；请基于最新正文重新生成。新候选会替代旧的待应用候选。切换文稿不会把候选应用到另一篇笔记，删除或同名重建文件也不会让旧候选接管新文件。

原有“撤回上次修改”处理最近一次成功应用的整篇/选区候选，仍要求全文精确匹配；0.3.0 局部工具操作使用各自卡片的“撤回”，可以保留可确认的后续无关变化。无法安全校验时拒绝覆盖，可查看记录或保存的旧版本再决定如何继续编辑。重命名会跟随当前文稿更新关联，跨应用移动或重新创建导致身份无法确认时，需要重新生成。

会话按文稿隔离保存；历史会标记伙伴、模型、候选未应用、已应用、已放弃、已撤回或失效状态，模型输出不会自动成为已验证素材。清空当前会话不会删除正文，保留本文要求与最近撤回记录。

## 停止与失败

点击“停止”会立即退出本地生成状态、作废未提交调用及迟到结果，并中止底层网络连接。不能保证服务端停止计算或停止计费。已完成的工具写入保留操作回执；部分回答仅为中断材料，不会产生新授权。插件关闭或重启后会标记中断，不会自动重发请求。

遇到错误，先查看提示并检查服务配置。未执行的调用不会因失败写入；执行后模型回复失败时，已完成修改会明确保留并提供操作记录。插件没有自动重试；已经收到部分内容后，也不会隐蔽地重新请求全文。同一要求若已经执行，不应因回复失败重复写入。数据损坏或来自未来版本时拒绝加载并保留原数据，不会静默重置。

## 内容与能力边界

写作请求会将**目标文稿最新全文、本文要求、全局偏好、当前伙伴规则与本文会话**提交给你选择的模型服务商；意图判断只使用本轮要求，协议探测使用合成材料。API 密钥只进入认证请求头，不进入提示词、会话、文稿或普通日志。

本地插件数据包含会话、候选基线、候选正文、撤回版本和局部操作回执，可能随你的同步方案同步；这些内容没有由稿伴加密。不要把会话存储理解为密钥保险箱。本插件不会扫描全库内容，不展开双链、图片或嵌入；普通写作请求不自动读取用户仅提供的网页链接。每日选题单独采集上述公开来源和原始材料，不表示事实已全部核验；绑定选题库时仅列出 Markdown 路径供明确选择。

插件自身免费使用，无需注册稿伴账户。你选择的第三方模型服务可能要求账户、API 密钥并按用量收费；这些费用和服务方数据处理条款由该服务商决定。无需认证的本地兼容服务也可使用。稿伴没有自建服务器、遥测或广告，也不会自行安装或更新插件及依赖。

“发布前检查”只检查当前文章与发布文案，不表示已经联网核实事实、验证最新平台限制或在公众号后台发布。插件没有通用联网搜索、RAG、自动多伙伴流水线、封面生成、公众号 HTML 排版或后台发布。公开来源的只读请求可在网络或服务端失败时最多重试一次，模型请求不自动重试。

桌面请求使用 Node HTTP/HTTPS，避免浏览器 CORS 限制，支持流式与取消。它不会自动继承 Chromium 的系统/PAC 代理；需要依赖这种代理的网络环境，应先通过独立聊天测试确认连接。插件不会自动跟随重定向转发密钥。

## 开发与本地模拟

```sh
npm install
npm test
npm run build
npm run package
```

构建生成 `main.js`，打包只将 `main.js`、`manifest.json`、`styles.css` 放入可安装目录 `dist/draft-companion/`、带版本号的目录和 ZIP。本地构建没有发布、推送、社区审核或文章发布动作。

本地构建不会发布。GitHub Actions 在 `main` 推送或 Pull Request 时检查代码；只有显式推送与 manifest 版本一致的纯数字版本标签（如 `0.1.0`）才构建并发布 Release。首次创建仓库时已配置此流程。

无需真实密钥即可验证流程：

```sh
node scripts/mock-provider.mjs --port 43127 --delay 20
```

在专用测试 Vault 中使用 `http://127.0.0.1:43127/v1`，不填写密钥，获取并选择 `mock-draft-model`。测试输入可用 `TEST:DISCUSS`、`TEST:EDIT`、`TEST:REVIEW`、`TEST:TITLE`；`TEST:SLOW` 便于测试停止。精确测试修改可写 `TEST:EDIT TEST:REPLACE("原词", "新词")`。模拟服务遵守冻结范围，保持选区之外的内容。

该服务只有确定性模拟响应，不代表真实模型能力。**仅发送合成测试材料**：`GET http://127.0.0.1:43127/__requests` 可查看仅保存在内存中的测试消息，用于检查最新全文和历史；不记录请求头或密钥，服务退出后记录消失。
