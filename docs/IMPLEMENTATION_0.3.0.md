# 稿伴 0.3.0 实现说明

0.3.0 在现有 TypeScript、Obsidian 控件、句级审阅与 Node HTTP/HTTPS 传输上加入受限工具运行时。未增加 Agent 框架、数据库、网页抓取或任意文件执行器。用户流程和回退操作见 [UPDATE_0.3.0.md](UPDATE_0.3.0.md)；实际验证结论由 [VERIFICATION_0.3.0.md](VERIFICATION_0.3.0.md) 单独记录。

## 请求与权限

`controller.ts` 的 `sendAgent` 接收本轮任务和范围，冻结目标、服务、模型、角色、偏好、本文要求、历史及最新全文。源文缓冲优先于落盘文件；侧栏聚焦不改变文稿绑定。发送时记录单个选区或插入光标，网络期间收集目标文稿的连续变更链。

`agent-intent.ts` 只把当前用户输入提交给意图判断，不从文稿或历史获得执行授权。本地 `constrainIntent` 再约束结果：明确拒绝写入保留只读路径；讨论 JSON 或询问如何修改不会直接执行；替换需要选区或用户本轮逐字引用的唯一原句；插入需要正文中的冻结单点。选题默认一个，只有当前用户明确数量时才允许二至八个。目标不明确时返回必要澄清，不猜测写入范围。

显式讨论、标题和大纲走普通回复；审阅和改稿建议复用既有批注与候选流程，用户采纳前不写入。角色原规则不被覆盖，运行时只在本轮增加固定协议；“选题编辑”等角色名称不构成写入许可。

## 工具协议与循环

`agent-runtime.ts` 提供原生和结构化兼容协议。自动探测使用合成 `protocol_probe` 请求，不带文稿、不产生文件操作。原生工具成功则缓存 `native`；明确不支持的接口/参数，或正常结束而没有原生调用的探测响应，可选择 `structured`。认证、网络、超时和不完整探测保持失败，不切换协议。能力缓存键依据服务 ID、根地址、模型和密钥引用生成；高级设置可明确指定协议。

原生协议使用完整 `tool_calls`。`provider.ts` 对非流式与流式工具调用校验名称、ID、索引、参数 JSON 和结束状态，拒绝不完整调用、重复/冲突 ID、截断和不兼容结构。请求声明 `parallel_tool_calls=false`，执行器顺序处理返回调用。

兼容协议只接收当前轮的完整 `{calls, reply}` 封装；调用项只允许 `id`、`name`、`arguments`。有调用时 `reply` 必须为空，最终回复 `calls=[]`。每轮最多八个调用，执行循环最多六轮；同一调用 ID 必须对应同一签名，重复 ID 复用已有结果而不重执行。

最新全文在请求上下文中只有一个固定标记块。执行后刷新该块，读工具返回引用、版本及条目元数据，不再次返回整篇文稿。估算容量超限时拒绝继续，不静默截断、摘要或丢弃历史。已成功操作后后续超时、停止或循环超限，保留回执并如实显示已完成修改。

## 八个受限工具

`agent-tools.ts` 对工具名、必填字段、参数类型、未知字段和本轮 opaque 引用做本地校验。模型不能提供路径或任意偏移。文稿、选题、范围和插入引用只属于当前请求；撤回 ID 必须属于当前文稿中本轮已知的操作。

| 工具 | 本地约束 |
|---|---|
| `read_document` | 返回最新哈希、授权引用、任务和操作元数据，不重复全文 |
| `list_topic_items` | 返回冻结请求解析出的顶层条目，保持同一请求引用，不自动换选 |
| `set_topic_checked` | 仅 `select-topic`；仅将已授权任务单个状态字符改为 `x`，不取消其他项 |
| `replace_text_range` | 仅 `replace`；使用被冻结的范围引用，禁止空替换删除 |
| `insert_text` | 仅 `insert`；使用被冻结的单点引用，禁止空插入 |
| `propose_edits` | 仅 `propose`；形成候选，工具自身不写正文 |
| `reveal_location` | 只定位当前请求已知且仍有效的范围、插入点或条目 |
| `undo_action` | 仅明确 `undo`；验证已有局部操作回执后撤回 |

选题数量预算在首次尝试时固定；不能因为条目冲突改为继续勾选其他条目。勾选后的标题与理由通过侧栏回复展示，不进入选题文件。写入核验和定位分别反馈，定位失败不会掩盖已完成写入。

## Markdown 选题解析

`topics.ts` 使用 `markdown-it` 块结构识别顶层任务，而不是对全文逐行找所有 `[ ]`。排除 frontmatter、围栏和缩进代码、HTML、引用及嵌套子任务；父任务可以保留其原始块内容。支持无序/有序列表、普通空白、NBSP 未勾选标记及 `[x]`/`[X]`，不把其他自定义状态当作普通选题。

条目保留原始 `from/to/statusFrom/statusTo/raw`、标题、完成状态、所在标题区段、说明和链接。NBSP 只在解析副本中转为空格；原始位置仍按 UTF-16 和原有 CRLF 计算，写入不重新序列化 Markdown。重复标题保持独立 opaque 引用，不能以标题去重或匹配第一处文字。链接只作为已有材料，解析不意味着读取链接内容。

## 局部写入与撤回

`agent-actions.ts` 维护授权锚点、操作回执及文稿连续版本。`trackContext/mapContext/replayAnchor` 回放网络期间变更，随后通过文稿事件继续映射；全局回执链不重复消费已经处理的事务。输入事务必须由 before 文本精确产生 after，未知变更、断链或重叠修改保守失效。

应用前检查意图、目标引用、锚点、正文边界和写入互斥，并保存 `prepared` 回执。`Documents.applyRangeValidated` 在最后全文比较与同步验证之间不让出执行权：源文使用编辑器事务，没有源文缓冲时使用 `Vault.process`。最终验证再次检查停止状态、目标、字符边界和 frontmatter，拒绝同路径替换文件或旧快照覆盖。

成功后重新读取真实编辑缓冲或文件，核验 replacement，再记录 `applied`。回执保存局部修改前文字、替换文字、目标及短前后文、请求身份、文稿路径、全文哈希与状态。持久化失败明确反馈，保留内存记录以防重复执行；实际写入但核验失败标为待检查，不能把该结果当作可重试的零写入。

撤回先核验实际局部文字与上下文，再执行同一路径的局部反向写入，并再次读取验证。已知无关事务更新锚点及当前核验哈希；重叠或上下文变化阻止撤回。只有可证明对应同一回执的单个原生 undo/redo 事务才同步状态。重启或未知外部写入需要完整哈希及局部文字同时一致；首个新事务不能使未核实的旧版本重新可信。

旧整篇候选和旧整篇撤回仍使用原有严格全文比较。对 CRLF 文件继续保留现有宿主保护：源文 Editor API 可能统一整篇换行，因此检测到落盘 CRLF 时拒绝源文写入；无源文缓冲且文件仍是 CRLF 才能走原始字符串更新。自动定位不能以切换模式绕过该保护。

## schema 3 与文件身份

`store.ts` 的数据版本为 3。增加 `topicLibrary`、`toolCapabilities`、消息 `presentation/actionIds`、`agentActions` 和文稿 `nativeId`；`agent-validation.ts` 严格校验回执字段、状态、锚点长度和文稿关联。旧服务与 `secretRef`、自定义规则、偏好、会话、候选和撤回资料保持原值。保存继续使用串行深拷贝快照，失败不会阻塞后续保存。

`Store.migrate` 对 schema 1/2 先验证，再等待 `main.ts` 完成原始字节备份与回读比较，成功后迁移 schema 3。未来版本、未知字段或损坏数据拒绝加载。运行中消息、准备中工具操作和中断候选在重启后转为中断/待重检，不自动请求模型或再次执行。

`document-identity.ts` 仅针对已经授权的 `TFile` 读取桌面文件元数据；在可用时以设备号、inode 和 birth time 组合形成 `nativeId`。恢复既有文稿需要路径、ctime 与已保存原生身份相符，不能仅凭相同路径或相同文本接管旧记录。文件系统元数据不可用时，不增加强恢复保证。

legacy 记录未保存 `nativeId` 时，可接受应用中明确移交的同一现场 `TFile`；无现场移交时保留会话历史、标记旧候选 `stale`、旧 undo `needsCheck` 及批注/回执待重检，再建立当前原生身份。身份无法确认不删除历史，也不静默恢复执行按钮。实际正文的恢复独立于插件数据回退。

## 呈现、密钥和交付

`message-render.ts` 将历史改稿 JSON、审阅 JSON 和 `summary/edits` 显示为只读摘要；未知结构保留查看入口，不授予执行能力。只有本地工具回执呈现已写入、定位和可核验撤回状态。侧栏保留对话/批注阅读区、更多操作、可滚动输入、发送/停止和独立审阅标签；执行细节留在本地操作反馈，不要求用户填写工具参数。

密钥选择使用官方 `SecretComponent`，运行时由 `SecretStorage` 获取，普通数据保存 `secretRef`。认证只通过请求头发送。插件不增加全库内容扫描、链接展开、远程媒体下载、Shell、公众号后台或自动发布工具。

`scripts/package.mjs` 从三个固定运行文件生成安装目录、版本目录及 ZIP，不遍历用户目录或打包 `data.json`。本地打包不创建 Release、不推送标签，也不更新社区目录。

专项测试覆盖协议完整性、意图约束、请求引用、重复调用、选题格式、位置回放、停止竞争、真实写入核验、存储失败、迁移与文件恢复等路径。自动测试、模拟服务、桌面 UI 和真实服务四类证据分别记录；本说明不把模拟调用或已有历史验证当成当前真实模型验证通过。
