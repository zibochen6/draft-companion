# 稿伴 0.4.0 实现说明

保留 TypeScript、原生 Obsidian ItemView、esbuild 和现有 Node Provider/SecretStorage 路径。schema 4 由 Store 严格迁移，三个运行文件不打包用户数据。

## 业务分层

- agent-intent / agent-tools：exact/adaptive 选择策略，list → plan_topic_selection 冻结集合 → set_topic_checked。显式数量不足在写入前解释，重复调用不扩大集合。
- daily-sources：公开 GET、来源独立状态、列表最多两页、可取消/超时/体积上限、标准 TLS、DNS 地址绑定与本地地址阻止；固定源不收到 Provider 认证。TUN benchmark 假 IP 仅在 HTTPS 有效公开域名下兼容。
- daily-protocol / daily-pipeline：最多两次模型请求，来源 ID 白名单、完整 JSON/stop 校验、逐字证据、0–5 优选、0–10 候选；第二次请求为每个候选生成中文简介。旧未选项可按材料指纹变化复核。star、采集时间不参与事实指纹。
- daily-runner：固定文稿/设置/模型/角色快照，queued ready gate 先持久化，再共享 Controller 生成锁。停用作废未提交阶段；已提交内容保留回执和真实提示。
- daily-notes：独立插件管理标记、日期降序、同日推荐/备选计数局部更新+追加，稳定来源事实哈希标记防止重复，保留原始字符串与换行；新卡片采用中文简介、独立文章标题和折叠写作预设。
- daily-editor：通过宿主 CM StateField 和 block decoration 隐藏有效管理区内的原始标记，不删改文稿；选区或光标直接落到标记行时恢复显示，损坏/重复管理区和代码示例不隐藏。
- daily-receipts：准备记录先落盘，跟随实际连续变更映射，原生 undo/redo 对文本校验；批次撤回保留无关后续编辑，重叠修改不删用户内容。
- daily-scheduler：Asia/Shanghai 日历，最新到期日一次补跑，App local storage 本机开关和窗口租约；失败需显式重试。该租约不提供跨机器同步锁。

## 公开来源与缓存

生产采集实际使用以下路径，不需要给采集器配置模型服务密钥：

- AIHOT：`https://aihot.news/api/v1/items?mode=selected&window=24h&limit=50`，使用返回的 cursor 最多读取两页；`https://aihot.news/api/v1/hot-topics` 读取当前事件排序。要求 API `schemaVersion: 1`，按返回的事件和原始链接合并，不将精选时间线当成热点榜。
- Git Stars：`https://git-stars.org/zh/repositories/topic/ai?page=1&sort=created`，最多两页。创建时间排序只用于发现项目。受阻且已开启补充时调用 GitHub `https://api.github.com/search/repositories`，使用 AI topic、star 下限、近九十天创建及未归档非 fork 的搜索条件；结果明确标为 GitHub 补充。
- 原始材料：GitHub `https://api.github.com/repos/{owner}/{repo}/readme` 使用 raw 媒体类型读取 README，新闻使用采集结果提供的公开 HTTPS 原始链接。最多十条，两个并发；正文节选最多 8000 字符，截取明确标注且避免切断 emoji 代理对。无法读取的条目保留为待补材料，不能凭空成为优选。

每个 runner 默认持有独立的 `SourceResponseCache`，正式任务和无写入 preview 复用。采用 LRU 淘汰，最多 **128 个公开 URL 响应、16 MiB UTF-8 正文**；超大响应不进入缓存。每次仍访问来源，有 ETag 时发送条件请求，正常 304 复用完整中文正文；变化的 200 替换正文与 ETag。缺少完整缓存的 304 明确失败，不将空响应作为已读材料。

缓存只包含公开响应的状态、文本、URL、ETag 和内容类型，不保存 Provider、认证头、密钥或密钥引用；不落盘、不随知识库同步，插件重启后重新建立。模型请求不使用此缓存。Node 路径不自动继承系统/PAC 代理；TUN 兼容仍保留正常 TLS 证书校验和本地地址保护。

## 中文卡片与数据兼容

`TopicCard.description?: string` 是 schema 4 中的可选字段。严格持久化校验允许旧记录缺少该字段；有值时必须为非空、包含中文字符的单行文本，最多 180 字，控制字符和换行无效。新的第二阶段回复则必须为每条候选返回 description，建议一句 30–60 字的中文简介，允许英文项目名与术语。解析不会把来源原始英文简介默默当作中文介绍，也不会增加第三次翻译请求。

`SourceItem.summary` 保留原始来源自述，来源和原始材料指纹仍只依据来源事实计算，模型中文简介不参与去重。已有配置、官方密钥引用、自定义角色、历史、批注和旧回执不重新初始化，不因新增字段再升级数据版本。

推荐理由建议 40–80 字，直接说具体读者价值；缺口写作者动笔前要补齐的操作、截图、案例或事实出处，不把读取长度、HTTP 状态或采集日志混入卡片。工具描述、标题和开头不能承诺“绝对安全”“保证不违规”，没有用户真实试用材料不能写“亲测”“实测”。已有角色规则保留，由本轮运行时协议协调格式和权限。

## 原子写入

Documents.applyChangesValidated 所有不重叠范围基于同一全文版本，最终同步校验身份、缓冲一致性、frontmatter 和 UTF-16/CRLF 边界。源文缓冲使用一次 Editor transaction；无缓冲一次 Vault.process。源文编辑器对于磁盘 CRLF 仍拒写，避免整篇换行改动。单范围旧接口转调此实现，保持兼容。

批次生成不使用展示 DOM 作为写入来源，也不赋予模型任意路径、偏移或文件系统权限。正常聊天/批注功能继续通过原有机制。修改同步映射批注并使旧整篇候选失效。重启、删除、同路径重建或外部断链保守待重检。

整理已经生成的管理区同样受写入规则约束：先备份并回读校验，再确认批次条目和当前回执完全对应且未经用户修改，最后同步替换格式与映射回执。用户改过的标题、说明和勾选不重排、不恢复；无法证明完整对应时保留原文。此约束不表示现存批次已经完成整理，实际操作结果以验证记录为准。

## UI

固定行右按钮，文稿名弹性省略，运行状态只更新轻量节点。模型生成不会把每日进度塞入聊天回复。启动不清空未发送输入；长输入上限和内滚动、可滚动菜单、中文组词保护继续保留。清空聊天不会删除每日数据。记录弹窗提供真实来源及批次撤回入口。

选题日报每个日期只保留一行推荐与备选数量。优选以首推文章标题作为独立 Markdown 标题，checkbox 行仅包含项目/事件和短来源链接，标题不受勾选删除线影响；随后是中文简介、简短理由和切入角度。开头、三至五条提纲和四个备选标题放入原生折叠 callout；材料缺口单独折叠，无缺口不输出默认套话。采集失败和详细时间保存在插件记录，来源链接仍指向实际材料。普通阅读不会展示原始管理标记；编辑器用受控装饰隐藏，直接选择对应行时仍可查看和编辑真实文本。
