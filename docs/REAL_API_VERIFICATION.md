# 真实 API 与基本操作验证

验证日期：2026-10-06 至 2026-10-07，Asia/Shanghai。插件版本：0.1.0。

**结论：该 API 可以支持稿伴的核心操作，但不能称为所有请求都正常。** 模型列表、流式与非流式短回复、真实改稿候选、差异应用、撤回和冲突保护均已验证；同时实际发现一轮流式结束格式异常，以及模型多改了未要求修改的文字。

## 验证范围

- 根地址：`https://api.meai.cloud/v1`。实际使用 `/models` 和 `/chat/completions`，没有自动修改 API 根路径。
- 模型列表返回 **37 个模型**；聊天实测模型 ID 为 **`claude-haiku-4-5`**。未逐一调用全部模型，也未验证网关背后的模型来源。
- 网络测试直接使用插件生产网络模块。桌面操作使用真实 **Obsidian 1.12.7 / macOS ARM64**，在库外临时 TestVault 中安装生产 `main.js`。
- 只发送合成文稿。没有读取或修改日常笔记库的隐藏目录。
- 密钥仅通过测试进程标准输入和临时内存用于认证；未持久保存真实密钥。实际检查插件保存的数据，密钥明文不存在，普通服务配置只有密钥引用。

| 操作 | 实测结果 |
| --- | --- |
| 获取模型列表 | 成功，37 个模型，约 2.8 秒。 |
| 非流式聊天 | 中文及 emoji 完整返回，正常 `stop` 结束，约 6.1 秒。 |
| 流式短回复 | 3 个正文分片拼接正确，中文及 emoji 完整，正常 `stop` 结束，约 5.4 秒。 |
| 独立聊天测试 | 在真实宿主成功，不把文稿或会话消息加入测试请求。 |
| 六角色 | 选题、大纲、初稿、审稿、指定改稿、标题摘要均获得过实际完整回复；不是一次全程无失败的流水线。 |
| 初稿及正文改稿 | 有效 JSON 经插件字段校验形成候选；真实差异弹窗应用成功；说明和核实事项不进入正文。 |
| 精确改稿与撤回 | 一轮正文改稿约 59 秒生成候选，应用后撤回，全文与该次修改前完全一致。模型额外改字的问题见下方。 |
| 选区改稿 | 真实选区候选约 16.1 秒生成；移动光标后仍应用到冻结范围；中文及 emoji 正常，范围外字符逐字相同。 |
| 重复应用 | 第二次应用被拦截，正文未重复写入。 |
| 应用及撤回冲突 | 手工修改后，旧候选或旧撤回不会覆盖后续编辑。在真实编辑器中复用明确删除候选验证相同写回路径，无额外模型请求。 |
| A/B 隔离与停止 | A 实际收到流式文本后切 B，从侧栏停止；A 记录为停止，B 正文和消息基线完全不变。 |
| 密钥与数据 | 已保存的插件数据无密钥明文；临时密钥 getter 已恢复，测试内存变量已删除。 |

真实初稿保留了 frontmatter、作者判断、双链、嵌入、图片及外链引用和代码块。审稿与标题摘要只留在会话中，没有写入正文。本文要求的 400 字符测试目标没有完全满足：初稿正文为 422 个字符，这属于模型指令遵循情况，不影响插件范围保护。

## 实际异常与判断

1. **长回复的一次流式请求缺少完成原因。** 插件明确报错“流式响应缺少完成原因，不能确认生成完整”，没有将其当作完整改稿。后续换成 30 条短建议的人工复验成功接收首块并停止。没有修改协议去猜测成功，也没有自动重试或切换非流式。若该服务反复出现此问题，可在设置中手动关闭流式后重新测试；本轮只验证了短回复的非流式协议。
2. **模型没有严格只改指定词语。** 要求只将“容易”改为“可能”，模型还把开头一处“作者”改成了 `author`。frontmatter、作者判断与引用保留，额外改字在差异中可见，条件撤回已恢复原文。这证明候选需要人工预览，不能把提示词当作字符级编辑保证。
3. **有两轮早期测试被停止。** 初始测试使用 60 秒配置，用户拒绝的确认回复和指定改稿未完成该轮测试；桌面调试连接及基于墙上时钟的等待也出现干扰，不能仅据此断言是网关故障。后续改为 120 秒配置和单调计时，指定改稿复验成功。
4. **测试脚本的错误已单独修正。** 最初的选区／冲突步骤包含换行转义错误，未执行有效编辑器操作；已修正后重跑并全部通过。首次调试连接超时时，初稿请求实际已经成功，恢复后直接应用已有候选，没有重发初稿。原始失败记录保留，未当成产品成功记录。

检查中还修复了插件的两处成功判断：独立聊天测试必须正常完成且正文非空；普通讨论也不能把空／空白正文标为成功。新增 15 项回归验证，目前 **8 个文件、99 项自动测试全部通过**，类型检查、生产构建和 ZIP 检查通过。
