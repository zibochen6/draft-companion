# 稿伴 0.2.0 更新与回退

0.2.0 增加公众号句级批注、源文与 Live Preview 高亮、独立只读审阅标签、逐条采纳/忽略、自动下一条、批注追问与版本历史，以及可验证的逐条撤回。普通聊天、六套自定义角色、自动模型发现和整篇候选继续保留。

## 本地更新

本轮已更新并启用 `personal_database` 中的 0.2.0。升级前完整备份位于该库 `.obsidian/plugins/draft-companion/rollback-0.1.2-20261007/`，包含旧运行文件、旧 `data.json` 与启用列表；验证记录见 [本地安装结果](qa-0.2.0/local-install-verification.json)。该备份为用户本地数据，不进入分发包。

先停止生成并保存插件配置。禁用插件，备份安装目录的 `main.js`、`manifest.json`、`styles.css` 和 `data.json`；将本版本三个运行文件复制到 `<Vault>/.obsidian/plugins/draft-companion/`，再启用。不要覆盖 `data.json`，也不要删除 Obsidian 密钥管理器中的密钥。

首次读取 schema 1 时严格检查原数据；在同一插件目录创建并校验 `data-schema1-时间戳.backup.json`，成功后才迁移 schema 2。无法备份、数据损坏或来自未来版本时拒绝启动，原数据不会被静默重置。

原服务与密钥引用、所有自定义角色及规则、偏好、本文要求、消息、旧候选和旧撤回记录完整保留。重启的未完成请求标为中断，不自动重发。文稿身份、已验证全文哈希与引用匹配才恢复批注；外部修改或身份无法确认时转为待重检。

## 回退到 0.1.2

1. 停止生成并禁用 0.2.0；另外备份当前 schema-2 `data.json` 和三个运行文件。
2. 恢复升级前的 0.1.2 三个运行文件。
3. 将升级前完整备份或 `data-schema1-时间戳.backup.json` 复制为安装目录的 `data.json`。
4. 再启用插件。0.1.2 不理解 schema 2，不能只替换运行文件而保留新数据。

回退插件数据不会恢复文章。已明确采纳的正文修改仍在文稿中；需要撤回时先在 0.2.0 使用安全逐条撤回，或检查自己的文稿版本备份。新版批注与追问不会出现在旧版，当前 schema-2 备份可供再次升级恢复。

分发 ZIP 只含三个运行文件，不含配置、密钥、笔记、数据备份或测试请求。本次不提交、不推送、不发布新版本，不操作公众号后台。

## CRLF 文稿

Obsidian 1.14.4 的源文 API 在保存时会将整篇 CRLF 换行统一成 LF；实机也观察到切换阅读模式触发这一保存。插件检测到 CRLF 源文文件时会阻止写入。若需保留 CRLF，请先备份原始文件，避免以源文方式打开它；没有任何源文缓冲、文件仍为 CRLF 时，稿伴通过原始字符串与 `Vault.process` 保留范围外换行。关闭源文或切换模式后应重新审阅，但不能保证宿主已经保存的 LF 会自动还原。普通 LF 文稿可直接在源文和 Live Preview 中采纳。稿伴自身不做整篇换行标准化。
