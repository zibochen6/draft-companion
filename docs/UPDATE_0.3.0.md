# 稿伴 0.3.0 更新、使用与回退

0.3.0 增加受限工具执行流程：讨论不改文稿，审阅和改稿建议先形成候选；用户明确要求执行时，稿伴可以勾选一个选题、替换已经选中的文字或唯一引用的原句，以及在发送时冻结的光标位置插入内容。实际写入以本地操作回执为准，模型的普通回复或历史 JSON 不会自行执行。

本版为本地交付。安装包为 `dist/draft-companion-0.3.0.zip`，可安装目录为 `dist/draft-companion/`；二者只包含 `main.js`、`manifest.json`、`styles.css` 三个运行文件，不含笔记、配置、密钥或测试请求。本次不发布社区版本。先前公开版本与先前更新文档继续保留。

## 日常使用

打开并聚焦 Markdown 文稿，检查侧栏显示的目标文件。角色规则、本文要求和全局偏好继续保留；角色名称或规则不能授予额外文件权限。“更多操作”中的任务选择用于表达本轮工作，输入的明确要求和拒绝写入仍是边界。

首次试用可在独立测试 Vault 中使用 [0.3.0 合成选题与改稿文稿](../fixtures/稿伴0.3.0合成选题与改稿.md)，其中的项目、链接和描述只用于验证流程。

| 想做什么 | 使用方式 | 对文稿的影响 |
|---|---|---|
| 讨论、拟标题、列大纲 | 选择“讨论”“标题”或“大纲”，或明确说“只讨论，不要修改” | 零写入，结果留在侧栏 |
| 审阅全文或选区 | 选择“审阅全文”，或在批注区审阅当前选区 | 形成批注候选，逐条预览、采纳或忽略 |
| 预览改法、整篇改写 | 选择“生成改稿建议”“选区改稿”或“整篇改稿” | 形成候选，检查差异后应用 |
| 直接替换文字 | 选中目标段落，明确要求修改；也可在本轮逐字引用唯一原句并说明改法 | 只写入被冻结授权的局部范围 |
| 直接插入文字 | 在正文编辑器放置光标，明确说“在当前光标插入……” | 只在发送时的单点插入 |
| 撤回局部执行 | 使用实际操作卡片的“撤回”，或明确要求撤回已执行操作 | 校验回执后恢复对应局部，保留可确认的后续无关修改 |

生成后移动光标、修改选区或切换文稿，不会把已有授权移到新位置。没有单个有效选区、原句不能唯一定位、位置进入 frontmatter 或目标不清楚时，会要求重新明确范围。空替换不表示删除；删除仍使用独立的“删除当前范围”候选流程。

## 从选题库选一个

选题库使用普通 Markdown 顶层任务，例如：

```markdown
# 选题
- [ ] **示例项目** — 已有材料和读者价值。｜ https://example.com/project
- [ ] **另一个项目** — 尚待补充的事实。
```

1. 打开选题库，或在“更多操作 → 绑定选题库”中选择文件。没有可用绑定时，插件会让你明确选择 Markdown 文件；不会自行读取其他文件内容。
2. 输入“从这份选题库选一个值得写的项目，并打勾”。默认只选择一个；用户明确要求多个时数量上限为八个。同一请求选定条目后，不会继续换选并多次勾选。
3. 插件只将该条任务的状态字符改为 `x`，保留标题、说明、链接、空白及其他条目。代码块、引用和嵌套子任务不作为独立选题。重复标题是不同条目，通过本轮引用区分。
4. 写入后重新读取真实文稿核验，并尝试定位。定位失败会保留已完成写入，明确显示定位未完成；可从操作卡片再定位。
5. 理由、切入角度、首推标题和四个不同角度的备选标题只留在侧栏，不插入选题库。材料里的链接不会自动抓取；不能把链接存在当成已经阅读、实测或核实项目。

若只想获得建议，明确输入“只推荐一个选题，不要勾选”。该路径不会写入。标题方法仍使用此前引入的读者问题、材料依据和兑现约束，没有新增联网搜索、传播数据学习或爆款预测。

## 执行结果、停止和撤回

工具操作卡片区分已准备、已写入、已撤回和待重新检查；“已写入”由本地回执呈现，不能由模型文字伪造。勾选、替换或插入成功后会核验实际内容；保存回执失败时会提示保留当前窗口，不能据此重复执行。

停止会取消尚未提交的调用，并中止本地网络请求。停止或后续模型超时发生前已完成的写入会保留，并显示对应操作记录；失败不能把它描述成“没有修改”。同一请求或失败后原样重发的同一要求，不能重复执行已有写入。

局部执行撤回依赖连续编辑事务、局部原文和短上下文。后续无关编辑可以映射位置并保留；改动重叠、上下文改变或未知外部修改会转为待重检，不能搜索另一处相似文字替代原位置。原生撤回/重做只有在能够证明对应同一操作时才同步回执状态。整篇候选的旧撤回流程仍要求全文精确匹配，不能覆盖后续修改。

## 工具协议和服务配置

服务高级设置新增“工具协议”：

- **自动检测**：使用不含文稿的合成请求探测当前服务和模型，并按连接配置缓存结果。认证、网络和超时失败不会触发协议切换或隐蔽重试。
- **原生工具**：使用服务的 `tool_calls`；完整校验调用名称、ID、参数和结束状态后顺序执行。
- **结构化兼容**：使用本轮明确约定的命令封装，经同一套工具参数与权限校验执行。普通聊天、历史中的 `summary`、`edits` 或改稿 JSON 都不会因此成为命令。

工具执行循环最多六轮，每轮最多八个调用；超过上限停止后续操作，保留已经完成的回执。意图判断和自动协议探测是额外的模型请求，不属于“六轮执行循环”的次数承诺。该上限也不代表模型、网络或服务商能力已经通过真实验证。

API 密钥继续通过 Obsidian 官方密钥管理器和 `SecretStorage` 取得。普通插件配置只保存 `secretRef`，不保存密钥正文。服务地址、模型、规则和目标在每次发送时冻结；不增加任意文件路径、网页读取、Shell 或发布工具。

## 数据升级与文件恢复

首次读取 schema 1 或 schema 2 数据时，插件先严格校验旧数据，在安装目录逐字节备份为 `data-schema1-时间戳.backup.json` 或 `data-schema2-时间戳.backup.json`，再校验备份并迁移到 schema 3。备份失败、损坏数据或未来版本数据会阻止加载，原数据不会静默重置。

schema 3 增加选题库绑定、工具协议缓存、消息呈现信息、局部操作回执和可用时的原生文件身份 `nativeId`。原服务、密钥引用、自定义角色、偏好、本文要求、历史、旧候选和撤回资料保留。未完成请求在重启后标记中断，不自动重发。

桌面文件恢复会在路径和创建时间之外核对文件系统身份；同路径、同文本或同创建时间不能让重建文件继承旧执行权限。已保存强身份的记录仍需核验全文哈希、锚点和上下文，才能恢复安全撤回。文件系统身份不可用时，不宣称具备同等恢复保证。

旧记录没有 `nativeId` 时，只有当前应用中明确移交的同一 `TFile` 对象才能作为可信现场关联；没有这种关联时，旧候选失效，旧撤回与批注待重新检查。历史和保存的旧内容仍保留，不能仅凭相同路径恢复可执行状态。重新生成或重新审阅会建立当前文稿的新授权。

## 安装与回退

更新前停止生成并禁用插件，备份安装目录三个运行文件及 `data.json`。只替换 0.3.0 三个运行文件，保留 `data.json` 和 Obsidian 密钥管理器中的密钥，再启用插件。最低要求仍为 Obsidian 桌面版 1.11.4，不支持移动端。

回退时：

1. 停止生成、禁用 0.3.0，另存当前 schema-3 `data.json` 和运行文件。
2. 恢复对应旧版三个运行文件；回到 0.2.x 时恢复升级前的 schema-2 数据，回到 schema-1 版本时恢复相应 schema-1 数据。
3. 将升级前完整备份或对应 `data-schema*-时间戳.backup.json` 恢复为安装目录的 `data.json`，再启用旧插件。旧版不理解 schema 3，不能只替换运行文件。

回退插件数据不会恢复文章。已经完成的正文修改仍在文件中；需要撤回时先在 0.3.0 使用可核验的局部撤回，或检查自己的文稿版本备份。0.3.0 的新增操作历史不会出现在旧数据里，另存的 schema-3 备份供再次升级时使用。
