# 稿伴 0.3.2：修复选题执行与请求失败

用户输入“帮我选择一些适合的选题来创作公众号。以及同时给我合适的爆款标题参考。”时，旧版先额外请求模型返回意图 JSON，又没有正确识别“选择一些”。这会导致格式失败、错误澄清，或让模型尝试本轮不允许的写入。60 秒的请求总时限也包含模型思考和输出，旧提示没有说明超时发生在哪一步。

本版直接识别明确的选题指令，包括上述原句、“帮我选一个”“请直接打勾”。角色和选题库只能提供目标线索；仍需要用户指令，不能凭角色获得修改权限。没指定数量时只勾选首推一项，明确数量时按本轮授权处理，理由、角度、首推标题及四个备选标题留在侧栏。“只推荐，不要勾选”、否定、假设、引用和代码中的伪命令不会获得写入权限。不明确的要求仍会分类或澄清。

工具按当前意图提供，选题不再向模型提供局部改稿、插入或撤回工具；只推荐不提供勾选工具。内部执行器仍独立检查权限、文稿身份、原文锚点和写入预算。选题工具不再重复发送简介和链接，这些材料仍完整保留在唯一全文上下文中。条目引用、序号、章节及有效行号用于区分同名项目；行号随真实编辑事务映射，失效条目不会显示伪当前行号。

侧栏现在显示请求及执行步骤。超时会说明发生在哪一步，并区分本地等待时限与服务端超时。已完成的修改保留实际回执和撤回；同一失败任务已经写入时，重复发送不会再勾另一个题目。没有实际回执仍不能显示“已修改”。没有新增自动重试、协议切换或全文截断。

使用时打开选题库、选择选题编辑，直接发送原来的那句话即可。若只要建议，请明确说“只推荐，不要勾选”。顶部“清空对话”可用于开始一轮新测试；安装不会自动清空历史。
