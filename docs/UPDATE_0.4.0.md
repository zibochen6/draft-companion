# 稿伴 0.4.0 更新与回退

本地增量版，从 0.3.2 升级，不提交、不推送、不公开发布。英文插件名称和 ID 不变；最低 Obsidian 1.11.4，桌面版。

## 新功能

- 普通选题按质量选 0–5 个；明确数量才使用精确数量。只推荐仍不写正文，标题仍在侧栏。
- 文稿信息行右侧固定“立即选题”，点击后采集、去重、筛选、读原始材料、生成卡片并写入绑定库；可排队、停止、查看结果和安全撤回新增。
- 本机每日 09:00（北京时间），Obsidian 需打开，错过只补最近一个到期日。源全部失败不写空日刊，模型失败不自动重试。
- 公开来源 AIHOT；Git Stars 403 时明确使用 GitHub 官方 API 补充。最多候选 10，优选 0–5，原始材料读取 10；容量上限不是产量目标。
- 公开响应使用默认 128 条／16 MiB 的内存 ETag 缓存，正式任务与只读验证复用；不缓存模型服务密钥或配置，不落盘、不随知识库同步。
- 最新日期置顶，既有内容逐字保留，同日只追加事实新进展及管理状态，用户改过的卡片与勾选不覆盖。
- 新选题卡先展示独立文章标题，checkbox 只放项目/事件名和短来源链接，避免标题勾选后变成删除线；中文简介、简短理由和角度直接可见，开头、提纲、四个备选及待补材料折叠。无缺口时不写套话，日期只留一行推荐与备选数量，采集详情留在插件记录。
- 原始管理标记保留在 Markdown 中支撑去重和撤回，阅读与编辑界面隐藏；直接选择标记行时可查看原文。旧 schema 4 记录兼容可选中文简介，新结果在既有第二次请求生成，不改来源自述或事实指纹。

## 迁移和安装

schema 1/2/3 原始数据严格校验，先在插件目录写原始备份并回读一致，成功才升级 schema 4。保留 Provider、官方密钥引用、自定义角色、历史、批注与旧回执；新增每日设置、运行和批次去重记录。迁移失败不会覆盖原数据。未完成任务标记中断，不重发。

可读格式调整继续使用 schema 4，旧卡片缺少 description 字段仍能读取；存在时严格校验非空中文单行、最多 180 字。整理已有自动生成批次必须先备份、校验未经用户修改，并同步更新撤回回执；不能整段覆盖用户已编辑内容。是否已经整理当前批次，以实际验证记录为准。

三个运行文件是 `main.js`、`manifest.json`、`styles.css`。ZIP 不带用户数据、密钥、测试请求和源码映射。手动更新前备份这三个文件和 `data.json`，再替换运行文件并重载。

本地安装脚本通过实际 Vault adapter 备份和校验运行文件及数据，保存未发送输入、阅读位置、编辑器缓冲和选区。安装过程不写文章。每日开关独立于同步数据；设置 09:00 不会自动打开开关。本机已启用北京时间 09:00，首轮正式任务写入十个候选、其中五个勾选，原有文稿保留，详情见 [验证记录](VERIFICATION_0.4.0.md)。

本次 `personal_database` 已备份并加载 0.4.0。初次从 0.3.2 升级的回退目录为 `.obsidian/plugins/draft-companion/rollback-daily-0.3.2-1791427360771`，可读界面调整前的 0.4.0 备份为 `.obsidian/plugins/draft-companion/rollback-daily-0.4.0-1791430289756`。各目录内为同批次运行文件和数据；最终可读性及稳定性更新前的备份为 `.obsidian/plugins/draft-companion/rollback-daily-0.4.0-1791432640823`。后续操作应使用实际安装记录中最新经过校验的备份。初次安装证据见 [本地安装记录](qa-0.4.0/local-install-verification.json)。

## 回退

1. 先停止运行任务，在每日设置关闭本机定时开关。
2. 关闭/禁用稿伴，保存需要保留的新卡片或操作记录。
3. 回到 0.3.2 时，从插件目录 `rollback-daily-0.3.2-1791427360771/` 恢复全部三个运行文件和同一份旧 `data.json`；回到界面调整前的 0.4.0，可用 `rollback-daily-0.4.0-1791430289756/` 的成套文件和数据。其他安装使用各自最新经过校验的备份。
4. 重载对应插件。0.3.2 无法读取 schema 4；旧 0.4.0 也可能不识别新的可选字段，因此回退均应恢复同一批次数据，不能只换运行文件。

新选题卡属于普通 Markdown，回退插件不会删除它们。批次撤回仅删除本次新增且未被重叠修改的块；用户已修改的内容、未知外部修改或窗格分叉会阻止撤回。已写入但记录保存失败会明确提示，不得再次提交相同内容。

## 运行边界

没有后台常驻服务：退出 Obsidian、电脑休眠或断网时不能按时采集。补跑使用运行时可获取的近 24 小时素材，不重建过去多天的历史新闻。GitHub 未认证接口有速率限制；所有源状态和实际来源可查。Node 网络不自动继承系统/PAC 代理；支持正常 TLS 校验下的 TUN 基准假 IP，但不降低证书或本地地址保护。

真实模型验证保持原配置的 `deepseek-v4.1-flash` 和流式输出，60 秒上限超时，显式提高为 180 秒后第二阶段超时，显式提高为 300 秒后约 281 秒完成。没有自动重试或切换模型；既有 Provider 和角色配置保留，超时调整是明确操作。一般用户应按实际服务耗时设置超时，成功返回模型列表不代表完整选题流程能在原超时内完成。

公开 README/页面可能是限长摘录，会标注截取；所用出处不等于事实完全核验。创作潜质不预测爆款，不能编造亲测或省钱经历。停止本地任务不保证服务端停止计费。Windows、Linux、移动端及所有模型组合未逐一验证。
